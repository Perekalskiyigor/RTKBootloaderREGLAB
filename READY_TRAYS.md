# Готовые каретки

`ReadyTrays.py` — общий менеджер для WORK, DEMO и TRAY_TRANSFER.
В рабочие алгоритмы пока не подключён.

Каретка 1: ячейки 1–4. Каретка 2: ячейки 5–8.
ПЛК выставляет `True` после возврата пустой каретки на наш концевик.
После подтверждения четвёртой укладки Python однократно пишет `False`.
При запуске первый `True` также трактуется как пустая каретка: запуск после
перезапуска процесса с частично заполненными каретками требует восстановления
состояния или предварительного освобождения кареток. Состояние хранится в памяти.

## Инициализация в рабочем файле

```python
from ReadyTrays import ReadyTrays

ready_trays = ReadyTrays(max_state_age=3.0)  # Один объект на все столы.
```

## OPC-поток

В цикле обмена, после подключения:

```python
ready_trays.sync_opc(
    read_bool=lambda name: self.node(name).get_value(),
    write_bool=lambda name, value: self._write(name, value, ua.VariantType.Boolean),
)
```

Это пример для OPCClient из TRAY_TRANSFER. В WORK/DEMO адаптировать функции
к полным NodeId `ns=2;s=Application.UserInterface.OPC_karetka1` и `OPC_karetka2`.
Чтение должно обращаться к ПЛК, а не к кешу `shared_data`. Ошибки чтения/записи
не подавлять и не заменять значениями по умолчанию. При потере связи вызвать
`ready_trays.connection_lost()` и существующий обработчик аварии.
Для этих двух узлов не должно быть другого циклического писателя в OPC.

`sync_opc()` сериализует чтение и запись с резервированием. Сетевые callbacks
должны иметь таймаут; внутри них нельзя повторно обращаться к менеджеру или
ждать захвата робота. Не вызывать менеджер под `shared_data_lock`.

## Глобальная Cell и робот

Модуль выдаёт номер, но не присваивает `Cell` другого Python-модуля.
Присваивание должно оставаться в рабочем файле с `global Cell, Tray_robot`.
Не использовать `from ... import Cell` для изменения общей переменной.

Порядок в существующем алгоритме:

1. Захватить общий ресурс робота существующим механизмом.
2. Получить `slot = ready_trays.wait_and_reserve_slot(stop_event)`.
   При `None` завершить операцию. Ожидание должно учитывать все события останова
   режима; можно передать объект с `is_set()`, объединяющий эти события.
3. Забрать плату существующей командой. Для забора присвоить `Cell` номер
   исходной ячейки/ложемента, как сейчас. `slot['cell']` пока не использовать.
4. Перед укладкой вызвать `ready_trays.check_before_placement(slot)`.
5. Присвоить `Tray_robot = 2` и **`Cell = slot['cell']`** в рабочем файле.
6. Выполнить существующую команду укладки и дождаться подтверждения робота.
   В TRANSFER это `_send_robot_command(241)`; в WORK/DEMO сохранить их способ
   формирования команды готовой тары. Cell и Tray_robot должны успеть попасть
   в Modbus до команды, как в существующем обмене.
7. После успеха вызвать `ready_trays.confirm_placement(slot)`, затем выполнить
   существующий сброс `Cell`/регистра и освободить робота.

Пока робот работает, остальные столы не должны изменять глобальную `Cell`.
Блокировка менеджера не заменяет существующий захват робота: он также защищает
исходные ячейки, ложементы и брак. Если для брака надо обходить ожидание готовой
тары, использовать ожидание с таймаутом и освобождать робота между попытками.

При ошибке движения вызвать `placement_failed(slot, reason)` и обработчик
аварийного останова. Метод бросает `TrayStateError` и сохраняет резерв.
Отмена через `cancel_before_pick(slot)` допустима только до начала забора платы.
Всё после начала движения оборачивать обработкой исключений, чтобы ошибку
не принять за успешную укладку и не продолжить движения.

Удалить из подключаемых алгоритмов прежнее управление доступностью готовой
тары через `OPC_ready_tray_full`/счётчик четырёх ячеек. Счётчики общего количества
обработанных плат сохраняются отдельно. Брак этим менеджером не учитывается.
